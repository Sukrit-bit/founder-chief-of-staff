Why this exists

Most AI workflows help founders summarize more. The real bottleneck is deciding what deserves conviction, testing, or rejection.

Chat is not enough

Chat helps with thinking. It is weak at durable state, evidence maturity, artifact routing, and cross-session continuity.

Research needs pressure

Every serious hypothesis should move toward continue, narrow, experiment, park, pause, or kill. Otherwise it stays interesting forever.

Agents need a workspace

The agent becomes more useful when it can maintain files, run checks, log failures, and update protocols when the work changes.

A complete loop

The synthetic examples show why the system is not just a note pack. One loop reaches a decision. Another loop improves the OS after a bad run.

Example decision

Run a narrow discovery experiment on permit resubmission workflows. Do not promote the idea into a venture thesis yet.

Decision: experiment, do not promote
1
Raw signal
Permitting pain looks broad, but broad pain is not a startup wedge.
2
Pattern
The tighter workflow is the resubmission loop after city comments.
3
Problem candidate
Translate comment packets into missing-document lists, owner maps, and resubmission packages.
4
Experiment
Shadow one resubmission and interview expediters and contractors.
5
Decision rule
Continue only if the workflow saves time and reduces missed items.
6
Improvement rule
If the agent summarizes without logging, update the failure register and protocol before the next run.

Start in three commands

The framework is meant to be used. The starter script creates a clean local workspace from the repo templates.

git clone https://github.com/Sukrit-bit/founder-research-os.git
cd founder-research-os
python3 scripts/init_workspace.py ~/founder-research/my-next-idea

Built for founders

This is for the messy middle of discovery: when you have signals, conversations, and market heat, but not enough evidence to call something a real startup thesis.

Built with AI, not for AI theater

The human owns judgment, taste, and strategic calls. The agent helps maintain the workspace, preserve context, run checks, and turn corrections into better operating rules.
