# v0.3.1 Release Evaluation

Status: **passed; ready for publication**  
Release candidate: `v0.3.1`  
Evaluation authority: [`evals/release-v0.3.1/claim_contract.json`](../../evals/release-v0.3.1/claim_contract.json)

## Why This Release Exists

Version 0.3.0 had an accurate product story and honest proof boundaries. It still failed as external communication. The writing standard existed, but it was not registered in operating memory, selected for the release task or tested by the release command.

The release therefore proved a broader learning-loop failure: remembering a rule does not make the rule operational.

## Before And After

### Before v0.3.1

- The public release audit checked claims, consistency, runtime behavior, safety, links and visuals.
- Some published files contained the internal line `Style check: external style applied.`
- Public copy relied too heavily on internal terms.
- The external-writing standard was absent from task-time memory and control selection.
- No fixed case proved that the old failure would be rejected.

### After v0.3.1

- External writing is a registered source and task-time control.
- The control has retrieval, selection, rejected-candidate and accepted-candidate cases.
- The public release command runs a dedicated external-style audit.
- The evaluator proves it rejects the old marker-plus-jargon pattern.
- The README, landing page, launch essay and walkthrough lead with the founder outcome in plain language.
- Technical documentation retains the detail needed by builders.

## Evidence Boundary

The implementation and fixed cases provide structural and synthetic evidence. The recorded reader review is release evidence for these declared surfaces. General live comprehension and long-term same-class improvement remain unproved.

## Evaluator Failure And Repair Record

The first external-style run correctly failed the old release. It found dense internal language in the README and landing page, leaked style markers in the launch essay and walkthrough, and long sentences across the public front door.

The first implementation of the evaluator also treated Markdown lists and HTML command blocks as long sentences. That was an evaluator defect, not a writing failure. The extractor was corrected to handle headings, lists, code blocks and visible HTML separately. Its negative and positive self-tests remained green.

## Manual Reader Review

- **15 seconds:** The landing page explains the outcome first: the system helps an AI agent remember how the company works, carry work forward and catch known mistakes.
- **45 seconds:** The reader can distinguish trusted sources, bounded retrieval, task-time rules and evidence of whether a correction helped.
- **90 seconds:** The reader can tell what is runnable now, what is tested only with fixed cases and what remains unproved in live use.
