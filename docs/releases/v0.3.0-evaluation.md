## Before and After

### Before v0.3.0

The public project described a durable founder operating system and a continuous-improvement method. Canonical memory and failure handling existed as operating contracts, but public users could not run a queryable retrieval layer or inspect task-time control enforcement.

### After v0.3.0

The repository contains a runnable local reference implementation that compiles registered sources into a derived SQLite index, returns bounded source-aware context, selects relevant controls, evaluates candidate output, and records typed learning evidence. The public story now connects operating memory, efficient retrieval, getting work done, and bounded improvement as one product spine.

## Evidence Boundary

The implementation and fixed benchmark provide structural and synthetic evidence. Live general behavioral improvement remains unproved. Vector retrieval, an external graph database, Gmail and Calendar ingestion, hosted tenancy, and self-modifying policy remain deferred.

## Findings and Remediation

### Runtime control selection was initially over-broad

The first synthetic run passed 12 of 14 cases. One proof control did not match the verb “prove,” and the learning control triggered on a scope question merely because it contained the word “learning.”

Remediation: expand the proof trigger to include `prove`; narrow the learning trigger to actual failure, mistake, correction, or repetition language. Rerun the complete casebook and record the final result here.

Result: 14/14 cases pass after remediation. The context-budget case returned eight sources and 2,600 excerpt characters against limits of ten sources and 3,600 characters.

### The first strict documentation run found two migration omissions

The landing page did not contain the exact `canonical state` launch signal, and the rewritten README used `How It Works` instead of the required `What It Does` section contract.

Remediation: add the canonical-state language to the memory-with-authority explanation and restore the required README section name. The strict rerun passed 78 checks with zero warnings and zero failures.

### Visual review found stale diagram vocabulary and narrow-screen code clipping

The landing-page orbit still used the older `events / state / execution` vocabulary after the causal-spine migration. The narrow screenshot also made the command block difficult to consume.

Remediation: align the orbit to `sources / context / action`; add narrow-screen wrapping and overflow handling to the command block; regenerate the social-card PNG; rerender and inspect all surfaces.
