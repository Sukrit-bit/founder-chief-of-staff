# Failure Modes

## Purpose

Repeated mistakes should improve the OS.

The failure-mode register turns corrections into rules.

## Register Format

| Failure | Symptom | Cause | Prevention |
|---|---|---|---|
| Evidence inflation | A pattern is treated as validation. | Public research feels more certain than it is. | Use the evidence maturity ladder. |
| Scope collapse | A wedge is described as the whole company. | Current sprint dominates context. | Use abstraction guardrails. |
| Stale memory | Agent answers from old context. | Live state is not updated. | Update dashboard, working state, and artifact index. |
| Recommendation stall | Agent suggests a fix but does not implement it. | Autonomy boundary is too timid. | Implement low-risk fixes directly. |
| Public leak risk | Private edge appears in public docs. | Export is not separated. | Use redaction protocol and synthetic examples. |

## Operating Rule

If a failure repeats or is likely to recur, update the register and the protocol that should prevent it.
