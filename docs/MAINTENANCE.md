# Maintenance

## When To Update The OS

Update the workspace after:

- new source research;
- customer or expert conversation;
- new pattern;
- new problem candidate;
- material thesis change;
- release or sharing work;
- repeated operating failure;
- major sprint or handoff.

## Maintenance Checklist

1. Update the artifact itself.
2. Update the artifact index.
3. Update the dashboard if current priorities changed.
4. Update the decision queue if judgment pressure changed.
5. Update the pattern register if a reusable signal emerged.
6. Update failure modes if an operating mistake appeared.
7. Run the documentation or project OS check.

## Success Standard

The founder should not need to ask:

- Did we log this?
- Is this cross-referenced?
- What changed?
- What decision does this force?
- Is this safe to share?
