# Maintenance

## When To Update The OS

Update the workspace after:

- new source research;
- customer or expert conversation;
- new pattern;
- new problem candidate;
- material thesis change;
- release or sharing work;
- repeated operating failure;
- protocol or template change;
- major sprint or handoff.

## Maintenance Checklist

1. Update the artifact itself.
2. Add or refresh the metadata block when the artifact is strategic.
3. Update the artifact index.
4. Update the dashboard if current priorities changed.
5. Update the decision queue if judgment pressure changed.
6. Update the pattern register if a reusable signal emerged.
7. Update failure modes if an operating mistake appeared.
8. Update the continuous-improvement log if the OS changed.
9. Update the protocol-change log if a rule or template changed.
10. Run the documentation or project OS check.

## Success Standard

The founder should not need to ask:

- Did we log this?
- Is this cross-referenced?
- What changed?
- What decision does this force?
- What did the OS learn from this?
- Is this safe to share?
