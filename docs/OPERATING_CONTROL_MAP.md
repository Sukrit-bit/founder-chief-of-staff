# Operating Control Map

## Purpose

This map prevents a founder workspace from becoming a pile of overlapping documents.

It answers:

```text
Which system owns this fact, decision, action, or control?
```

## Default Read Order

1. Current decision dashboard.
2. State registry.
3. Current working state.
4. Artifact index.
5. The task-specific canonical source.

Do not load the whole workspace by default.

## Route Map

| Event or need | Canonical route | Boundary |
|---|---|---|
| Current focus changes | Dashboard and working state | Dashboard is not history |
| A strategic call is needed | Active decision queue | Agent prepares; founder decides |
| A relationship changes | CRM canonical records | Personal tasks do not rewrite CRM |
| A founder commitment changes | Personal execution console | Do not infer owner or date |
| A company is researched | Source case and capability map | Evidence is not automatic scope |
| Product work moves to another repo | Implementation handoff | Share minimum necessary context |
| A correction exposes recurrence | Improvement controller and control ledger | Logging alone is insufficient |
| A recurring job is added | Automation registry and contract | No contract, no scheduled write |
| External output is prepared | Data handling and safety check | Private proof stays private |

## Source-Of-Truth Map

| Need | Source of truth | Update trigger |
|---|---|---|
| Current focus | Current decision dashboard | Priorities or active bets change |
| Full continuity | Current working state | Phase, thesis, evidence, or blockers change |
| Authority and access | State registry | A canonical system or boundary changes |
| Navigation | Artifact index | A current artifact or route changes |
| Founder judgment | Active decision queue | A call needs preparation |
| Relationships | CRM | A person, organization, interaction, introduction, or opportunity changes |
| Founder execution | Daily operating console and canonical tasks | Commitments, dates, blockers, or carryovers change |
| Capability intelligence | Capability map | A company case yields a transferable capability |
| Scheduled work | Automation registry | A recurring workflow changes |
| Repeated failures | Failure-mode register | A material or recurring failure appears |
| Structural repair proof | Autonomy-control ledger | A systemic repair is opened, tested, or closed |

## Write Rules

- Update the smallest authoritative surface.
- Reconcile every implicated system in the same event.
- Preserve raw captures where a contract requires it.
- Read back changed records.
- Cross-reference instead of duplicating narrative.
- Record contradictions rather than choosing a convenient source.
- Treat external, destructive, sensitive, and strategic actions as human-gated.

## Completion Standard

A cold reader or new agent should know:

1. what changed;
2. where the current truth lives;
3. what decision remains;
4. what action is next;
5. what was verified;
6. what is still uncertain.

Style check: external style applied.
