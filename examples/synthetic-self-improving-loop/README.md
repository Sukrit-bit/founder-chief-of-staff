# Synthetic Example: Self-Improving Loop

This is a fictional example.

It shows how Founder Research OS turns a weak agent run into a better operating system.

## Synthetic Setup

A founder is exploring AI tools for permit expediters.

The founder shares a customer conversation about teams losing time when permit corrections arrive from the city.

The first agent response is weak. It summarizes the conversation but does not update the workspace.

## What The OS Catches

The failure is not bad prose.

The failure is that the agent did not create decision pressure.

It should have:

- created an evidence artifact;
- updated the pattern register;
- updated the decision queue;
- logged the repeated risk;
- changed the protocol so the mistake is less likely next time.

## Example Loop

```text
bad_agent_output.md
-> failure_mode_register.md
-> protocol_change.md
-> improved_next_run.md
-> operating_review.md
```

## Decision

Current status: `Continue`.

The opportunity is not proven.

The OS is better because the failure created a reusable rule:

```text
If an input changes project state, do not stop at summary.
Create or update the artifact, queue, and index.
```
